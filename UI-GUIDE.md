# UI Guide

The goal is not to make every application look identical. The goal is to avoid redesigning ordinary application interactions from scratch.

## Principles

- Clarity before decoration.
- Keep one obvious primary action on a page where possible.
- Put search and filters near the data they affect.
- Use sensible defaults so users do not have to configure a page before it becomes useful.
- Prefer readable tables over card grids for structured business data.
- Avoid horizontal scrolling where practical; when a table genuinely needs width, make that behavior deliberate.
- Group related form fields and keep labels visible.
- Separate destructive actions from routine save/continue actions.
- Give immediate feedback after important actions.
- Use status color as reinforcement, not as the only way to communicate status.
- Empty states should explain what is missing and, when appropriate, what the next action is.
- Keep account settings separate from product administration.
- Maintain usable responsive behavior even when desktop is the primary environment.

## Default patterns

The `/patterns` screen is the living reference for the starter. It demonstrates:

- page heading and primary action
- compact summary values
- filter/search area
- list/table treatment
- semantic status badges
- form grouping and actions
- tabs
- empty states
- account settings layout

Copy or adapt those patterns before creating a new visual treatment.

## Visual character

The baseline is restrained and application-focused: neutral surfaces, clear hierarchy, modest rounding and shadows, compact spacing, and blue as the primary accent. Branding can change the accent and identity without changing every interaction pattern.
